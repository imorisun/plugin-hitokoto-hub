# 删除非最优句子服务器内部错误修复方案

## 摘要

用户反馈:点击「批量删除非最优句子」时出现「服务器内部错误」提示,且删除成功后相似度检查数据未刷新。

根因:`SimilarityCheckServiceImpl.deleteNonOptimalSentences()` 在无 SUCCESS 日志时返回 `Mono.empty()`,导致端点返回空 `Mono<ServerResponse>`,Spring WebFlux 报 500。前端因 500 进入 catch 分支,已有的刷新逻辑(`fetchLatestLog` + `fetchGroups`)未执行。

修复方案:在 service 层补全 empty Mono 兜底,并补充边界测试。前端无需改动(刷新逻辑已存在,后端修复后即可正常触发响应式更新)。

---

## 当前状态分析

### 后端:`SimilarityCheckServiceImpl.deleteNonOptimalSentences()` (L122-141)

```java
@Override
public Mono<Integer> deleteNonOptimalSentences() {
    return getLatestSuccessLog()
        .flatMap(latestLog -> {
            if (latestLog == null) {  // ← 死代码!flatMap 不会收到 null
                return Mono.just(0);
            }
            String algorithm = latestLog.getSpec().getAlgorithm();
            double threshold = latestLog.getSpec().getThreshold();
            return fetchAllSentences().flatMap(sentences -> {
                if (sentences.isEmpty()) {
                    return Mono.just(0);
                }
                return Mono.fromCallable(() ->
                    collectNonOptimalNames(sentences, algorithm, threshold))
                    .subscribeOn(Schedulers.boundedElastic())
                    .flatMap(this::deleteSentencesInBatch);
            });
        });
    // ← 缺少 .switchIfEmpty(Mono.just(0))
}
```

**empty Mono 传播路径**:
1. `getLatestSuccessLog()` 调用 `client.listAll(...).filter(...).next()`
2. 无 SUCCESS 日志时,filter 后为空 Flux,`.next()` 返回 `Mono.empty()`
3. `Mono.empty().flatMap(...)` 不执行 lambda,直接传播 empty
4. `deleteNonOptimalSentences()` 返回 `Mono.empty()`
5. 端点 `deleteNonOptimal` 的 `.flatMap(count -> ServerResponse.ok()...)` 不执行
6. 端点返回空 `Mono<ServerResponse>`,Spring WebFlux 抛 500

### 端点:`SimilarityCheckConsoleEndpoint.deleteNonOptimal()` (L188-192)

```java
private @NonNull Mono<ServerResponse> deleteNonOptimal(@NonNull ServerRequest request) {
    return similarityCheckService.deleteNonOptimalSentences()
        .flatMap(count -> ServerResponse.ok()
            .bodyValue(Map.of("message", "批量删除完成，共删除 " + count + " 个句子", "deleted", count)));
}
```

端点本身逻辑正确,但因 service 返回 empty Mono 而失效。无需在端点层加 `switchIfEmpty`(应在 service 层根治)。

### 前端:`SimilarityCheck.vue` `handleBatchDeleteNonOptimal` (L709-738)

```javascript
onConfirm: async () => {
  batchDeleting.value = true
  try {
    const {data} = await axiosInstance.post<{message: string; deleted: number}>(
      `${BASE}/similarity-check-groups/-/delete-nonoptimal`,
    )
    toast.success(data.message || '批量删除完成')
    // 重新加载数据
    groupPage.value = 1
    await fetchLatestLog()
    await fetchGroups()
  } catch (e: any) {
    toast.error(e?.response?.data?.message || '批量删除失败')
  } finally {
    batchDeleting.value = false
  }
}
```

刷新逻辑已存在且正确:`fetchLatestLog` 更新 `latestLog.value`,`fetchGroups` 更新 `groups.value` 和 `groupTotal.value`,均通过 Vue 3 `ref` 触发响应式视图更新。**后端修复后,此段会正常执行,无需改动**。

### 测试缺口:`SimilarityCheckServiceImplTest.java`

现有 6 个测试,其中 `deleteNonOptimalSentences` 仅覆盖正常流程(有日志+有句子)。缺少「无 SUCCESS 日志」的边界测试,正是 bug 场景。

## 提议变更

### 变更 1:修复 `deleteNonOptimalSentences()` empty Mono 问题

**文件**:`src/main/java/top/puresky/hitokotohub/service/impl/SimilarityCheckServiceImpl.java`

**位置**:L122-141

**改动**:
- 删除 `if (latestLog == null)` 死代码(`flatMap` 不会收到 null,此分支永不执行)
- 在链末尾添加 `.switchIfEmpty(Mono.just(0))`,确保无 SUCCESS 日志时返回 0 而非 empty Mono

**修复后代码**:
```java
@Override
public Mono<Integer> deleteNonOptimalSentences() {
    return getLatestSuccessLog()
        .flatMap(latestLog -> {
            String algorithm = latestLog.getSpec().getAlgorithm();
            double threshold = latestLog.getSpec().getThreshold();
            return fetchAllSentences().flatMap(sentences -> {
                if (sentences.isEmpty()) {
                    return Mono.just(0);
                }
                return Mono.fromCallable(() ->
                    collectNonOptimalNames(sentences, algorithm, threshold))
                    .subscribeOn(Schedulers.boundedElastic())
                    .flatMap(this::deleteSentencesInBatch);
            });
        })
        .switchIfEmpty(Mono.just(0));
}
```

**为什么这样修复**:
- `switchIfEmpty` 在上游为 empty Mono 时提供默认值 `0`,语义清晰(无可检查日志 → 无需删除 → 删除 0 个)
- 删除死代码避免误导后续维护者(让人误以为 `flatMap` 会收到 null)
- 保留 service 层根治,端点层无需兜底,职责清晰

### 变更 2:补充边界测试

**文件**:`src/test/java/top/puresky/hitokotohub/service/impl/SimilarityCheckServiceImplTest.java`

**位置**:L185(`deleteNonOptimalSentences` 测试之后,类结束 `}` 之前)

**改动**:新增 1 个测试,覆盖「无 SUCCESS 日志」场景,防止回归。

**新增测试**:
```java
@Test
@DisplayName("deleteNonOptimalSentences：无 SUCCESS 日志 → 返回 0（不返回 empty Mono 导致 500）")
void deleteNonOptimalSentencesWithoutLog() {

    ReactiveExtensionClient client = MockExtensionClient.builder()
        .with(s1).build();
    SimilarityCheckServiceImpl service = new SimilarityCheckServiceImpl(client, groupBuilder, codec);

```

**为什么这样修复**:
- 直接覆盖 bug 场景,`verifyComplete()` 而非 `verifyEmpty()`,确保返回 `Mono.just(0)` 而非 `Mono.empty()`
- 回归保护:如果未来重构误删 `switchIfEmpty`,此测试会立即失败

### 前端:无需改动

`handleBatchDeleteNonOptimal` 中的刷新逻辑(L727-730)已正确实现:
- `groupPage.value = 1` 重置到第一页
- `await fetchLatestLog()` 更新日志状态(通过 `latestLog.value` 触发响应式更新)
- `await fetchGroups()` 重新获取分组数据(通过 `groups.value`、`groupTotal.value` 触发响应式更新)

后端 500 修复后,此段会正常执行,Vue 3 的 `ref` 响应式系统会自动更新视图。**无需任何前端改动**。

## 假设与决策

1. **根因定位**:通过静态分析确认 500 错误的唯一路径是 `getLatestSuccessLog()` 返回 empty Mono。其他路径(无句子、空非最优集合)均已正确返回 `Mono.just(0)`。
2. **修复层级**:选择在 service 层根治(`switchIfEmpty`),而非端点层兜底。原因:service 层契约应保证返回非 empty Mono,端点不应承担 service 层的 empty 处理职责。
3. **前端不改**:刷新逻辑已存在且正确,问题仅在 catch 分支被触发。修复后端后,刷新会自动恢复。避免无必要的改动。
4. **不并行化刷新**:`fetchLatestLog` + `fetchGroups` 串行 await 虽可并行化提升数十毫秒性能,但属过度优化,不在 bug 修复范围内,保持代码简洁。
5. **测试策略**:仅新增 1 个边界测试,不改动现有 6 个测试,降低回归风险。
