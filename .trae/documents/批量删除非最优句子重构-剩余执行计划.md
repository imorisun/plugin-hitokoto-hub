### 变更 3b:重构 `deleteSentencesInBatch`

**文件**:[SimilarityCheckServiceImpl.java](file:///c:/Users/19002/Documents/Trae/plugin-hitokoto-hub/src/main/java/top/puresky/hitokotohub/service/impl/SimilarityCheckServiceImpl.java) L280-298

**问题**:`deleteNonOptimalSentences` 在 L144 调用 `deleteSentencesInBatch(names, logName)`,期望返回 `Mono<BatchDeleteResult>`,但当前方法签名是 `Mono<Integer> deleteSentencesInBatch(Set<String> names)` — 编译错误。

**改动**:
1. 签名改为 `private Mono<BatchDeleteResult> deleteSentencesInBatch(Set<String> names, String logName)`
2. 用 `defaultIfEmpty(false)` 区分"未找到"与"成功删除"(当前 `switchIfEmpty(Mono.empty())` 静默吞掉未找到)
3. 用 `reduce(new int[]{0, 0}, ...)` 累加 `[deleted, failed]`,取代只统计成功数的 `reduce(0, Integer::sum)`
4. 返回 `BatchDeleteResult.of(total, deleted, failed)`,空集合时返回 `BatchDeleteResult.empty("无非最优句子需要删除")`
5. 完成日志补 `total/deleted/failed` 三元结构,便于问题定位

**目标代码**:
```java
private Mono<BatchDeleteResult> deleteSentencesInBatch(Set<String> names, String logName) {
    int total = names.size();
    if (total == 0) {
        log.info("批量删除：无非最优句子待删除, log={}", logName);
        return Mono.just(BatchDeleteResult.empty("无非最优句子需要删除"));
    }
    log.info("批量删除：共 {} 个待删除, log={}", total, logName);

    return Flux.fromIterable(names)
        .flatMap(name -> client.fetch(Sentence.class, name)
            .flatMap(s -> client.delete(s)
                .thenReturn(true)
                .onErrorResume(e -> {
                    log.warn("删除句子 {} 失败: {}", name, e.getMessage());
                    return Mono.just(false);
                }))
            .defaultIfEmpty(false), 16)
        .reduce(new int[]{0, 0}, (acc, ok) -> {
            if (ok) acc[0]++; else acc[1]++;
            return acc;
        })
        .map(counts -> {
            int deleted = counts[0];
            int failed = counts[1];
            log.info("批量删除完成：log={}, total={}, deleted={}, failed={}",
                logName, total, deleted, failed);
            return BatchDeleteResult.of(total, deleted, failed);
        });
}
```

## 异常处理策略矩阵(沿用设计文档)

| 异常来源 | 处理策略 | 理由 |
|---|---|---|
| `client.fetch` 返回 empty(句子已被并发删除) | `defaultIfEmpty(false)` → 计入 `failed`,继续 | 数据竞态,需可见 |
| `client.delete` 单条抛异常 | `onErrorResume` 跳过,计入 `failed`,继续 | 项目硬约束:单条失败不中断 |
| `client.listAll(Sentence)` 失败 | `doOnError` 记日志,传播到端点 → 500 | 数据访问失败,整体无法继续 |
| `collectNonOptimalNames` 算法异常 | `doOnError` 记日志,传播到端点 → 500 | 算法 bug 不应静默 |
| `getLatestSuccessLog` 返回 empty | `switchIfEmpty` 返回 `BatchDeleteResult.empty(...)` | 业务正常路径 |
| `fetchAllSentences` 返回 empty list | flatMap 内返回 `BatchDeleteResult.empty(...)` | 业务正常路径 |
| 端点层任何异常 | `onErrorResume` → 500 + 结构化错误体 | 统一错误响应格式,前端易解析 |

## 假设与决策

1. **沿用已批准的设计**:本计划不重新设计,仅执行上一轮已批准的 [`批量删除非最优句子功能全面重构方案.md`](./批量删除非最优句子功能全面重构方案.md) 的剩余部分。所有关键设计权衡(端点兜底而非 `@ControllerAdvice`、`BatchDeleteResult` 放 `service/dto/`、`IllegalArgumentException` 映射 500 而非 404 等)均维持原决策。

2. **不修改前端**:[SimilarityCheck.vue](file:///c:/Users/19002/Documents/Trae/plugin-hitokoto-hub/ui/src/components/SimilarityCheck.vue) 已实现乐观更新 `removeAllNonOptimalFromGroups()` + `fetchLatestLog()` + `fetchGroups()`,并通过 `data.message` / `data.deleted` 解析响应。新增的 `total` / `failed` 字段对前端透明(不破坏现有解析)。

3. **不修改 `SentenceReconciler` 和算法层**:已确认 `SentenceReconciler` 删除时仅 `log.info` 无副作用,`SimilarityGroupBuilder` 通过 `profileMap::get` + `filter(Objects::nonNull)` 自动过滤已删除句子。

4. **端点构造函数依赖**:端点构造函数为 `(ReactiveExtensionClient, SimilarityCheckService, SettingConfig)`。测试 `deleteNonOptimal` 时,`client` 和 `settingConfig` 不会被调用,可传 mock 占位。

5. **`MockExtensionClient` 的 `delete` 返回 `Mono.just(ext)`**:所以 `client.delete(s).thenReturn(true)` 在 MockExtensionClient 场景下永远成功。要测试"单条删除失败"和"句子已不存在"场景,必须用纯 Mockito mock 精确 stub `client.delete` / `client.fetch` 的返回值。

6. **执行顺序**:严格按 3b → 4a → 4b → 5 → 6 → 编译验证 → 受影响测试 → 全量回归 顺序执行。3b 和 4a 是编译阻塞点,必须先完成才能验证任何测试。
