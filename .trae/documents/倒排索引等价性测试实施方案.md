**Fixture 生成策略** — `generateProfiles(int n, long seed)`:

```java
private static List<SentenceProfile> generateProfiles(int n, long seed) {
    Random rnd = new Random(seed);
    // 10 个互不相同的古诗词模板,确保跨模板无 bigram 共享
    String[] templates = {
        "春风又绿江南岸", "明月何时照我还", "千山鸟飞绝", "万径人踪灭",
        "孤舟蓑笠翁", "独钓寒江雪", "白日依山尽", "黄河入海流",
        "欲穷千里目", "更上一层楼"
    };
    List<SentenceProfile> profiles = new ArrayList<>(n);
    for (int i = 0; i < n; i++) {
        String base = templates[i % templates.length];
        int suffixLen = rnd.nextInt(5); // 0-4 个随机后缀字符,制造相似但不完全相同
        StringBuilder content = new StringBuilder(base);
        for (int k = 0; k < suffixLen; k++) {
            content.append((char) ('a' + rnd.nextInt(26)));
        }
        profiles.add(new SentenceProfile(
            "sentence-" + i, content.toString(),
            "test-cat", "匿名", "未知", false, 0, 0
        ));
    }
    return profiles;
}
```

**特性**:
- n=1000 时,每模板派生 100 句,模板间无 bigram 共享 → 倒排索引候选数 ~49,500(对比暴力法 499,500,约 10x 削减)
- 模板内句子共享基础 6 个 bigram → 必然产生相似对,有效验证候选收集逻辑
- 随机后缀制造相似度梯度,避免全部 1.0 退化

**等价性断言辅助** — `assertPairSetsEquivalent(expected, actual)`:

```java
private static void assertPairSetsEquivalent(List<SentencePair> expected,
                                              List<SentencePair> actual) {
    assertThat(actual).hasSameSizeAs(expected);
    // 两种算法都用 i<j 顺序构建 pair,sentence1Name/sentence2Name 顺序一致
    Map<String, Double> expectedMap = new HashMap<>();
    for (SentencePair p : expected) {
        expectedMap.put(p.sentence1Name() + "|" + p.sentence2Name(), p.similarity());
    }
    Map<String, Double> actualMap = new HashMap<>();
    for (SentencePair p : actual) {
        actualMap.put(p.sentence1Name() + "|" + p.sentence2Name(), p.similarity());
    }
    assertThat(actualMap.keySet()).isEqualTo(expectedMap.keySet());
    // 相似度值应精确相等:同一 computeSimilarity 函数 + 同一 Math.round 截断
    for (String key : expectedMap.keySet()) {
        assertThat(actualMap.get(key))
            .as("pair [%s] similarity", key)
            .isEqualTo(expectedMap.get(key));
    }
}
```

**关键设计决策**:

1. **阈值统一用 0.3**:必须 > 0。原因 — 倒排索引依赖"相似度 > 0 ⟺ 共享 bigram"性质,若阈值=0 则暴力法会返回所有 pair(含 sim=0),而倒排索引会跳过无共享 bigram 的 pair,导致不一致。0.3 同时能筛选出模板内大部分相似对。

2. **用 Map key 集合比较而非 List 相等**:两种算法的插入顺序可能因 BitSet 迭代差异而不同,虽然最终都按 similarity 降序排序,但相同 similarity 的 tie 顺序可能不一致。用 key 集合比较避免 flaky。

3. **分发测试用 `isEqualTo` 直接比较 List**:对 n=499 和 n=500 的分发测试,`find()` 内部调用的就是 `findBruteForce` 或 `findWithInvertedIndex`,因此 List 应完全相等(含顺序),用 AssertJ 的 `isEqualTo` 做 deep equality 检查(record 自动生成 equals)。

4. **性能测试不严格断言 inverted < brute**:避免 CI 环境噪声导致 flaky。仅断言两者均 <10s,等价性由专门的等价测试保证。
